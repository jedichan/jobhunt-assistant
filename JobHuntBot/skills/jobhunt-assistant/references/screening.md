# 官方网站选岗与预筛

读取 `J/application_rules.md`、`J/candidate_profile.json`、`J/resume_routing.md`、`J/references/preliminary-pool-workflow.md` 和当前两池、日报、阻碍记录。初次找岗只需目标岗位、地点和必要排除条件，不要求先补完整个人资料或登录账号。

## 范围和来源

手动运行以当前请求和个人筛选规则为准；定时运行以用户确认的任务范围为准。未提供招聘届别、毕业窗口、城市或行业时，不沿用其他人的偏好。简历分类由个人 `resume_routing.md` 定义，不假设每位用户都有 A–E 五份版本。

指定公司时只围绕该公司检索。常规筛选优先近期发布、匹配度高且确实开放的职位，优先最近 24 小时，不足时可扩到 48 小时；不知道发布日期就标明未知，不把今日发现写成今日发布。

从现有 `job_url` 和来源记录寻找招聘入口，但历史链接必须重新核验。通过雇主官网确认招聘系统或外部 ATS 的官方关联，查看具体岗位职责、城市、签约主体、专业和技术要求、级别、截止日期及毕业/工作资格。第三方平台只作发现和交叉核验，不能替代官方依据。

按个人规则排除不合适的用工形式、地点、经验要求和已关闭岗位。行业和岗位名称不能代替 JD 匹配判断；相关方向但资格不明时保留待核验点，明确不符合硬条件时跳过。

## 数据边界

- 预筛不登录、不打开申请流程、不点 Apply、不填表、不上传。不能修改 `job_pool.csv` 或创建 `application_log.csv` 行。
- 按公司 + 岗位 + 地点 + 官方链接与两池去重，并检查相同 ATS 岗位 ID 的参数变体。既有 lead_id 不变；新 ID 可由规范化键的确定性哈希生成 `prelim-<12位摘要>`，冲突时增加摘要长度。
- 新行只用 Preliminary / Needs review，优先级 P1/P2/P3。填写现有表头中的已知字段：公司、岗位、城市、官方 URL、发现时间、可核实的发布/截止日期、匹配理由、资格依据、建议简历、阻碍与下一步。未知值明确留空或待核验。`user_decision` / `promoted_at` 留空。
- 只合并本轮新增线索、日报摘要和必要 blocker。摘要包含实际新增数、主要分类和最多五条值得审核的 lead_id，不把总池行数当本轮新增。
- 写后校验行数和重复 ID，确认正式池与申请记录未被本轮预筛改变。完成预筛不自动晋升；用户明确给出 lead_id 和推进要求后进入申请模式。

通过既有本地看板交付。无新增也如实说明，不自动打开浏览器或另建报告。
