# 求职定时任务

技能定义工作流程，本仓库默认不创建、启用或接入任何自动化。只有用户明确要求设置定时任务时才使用当前应用的自动化工具。普通预筛、Gmail 同步和浏览看板不修改调度。

先检查用户现有的匹配任务，优先更新，避免重复运行。新任务的范围、时区和频率来自用户要求；可以提供“每天 20:00 预筛、18:00 同步”的示例，但不能当作用户已选择的计划。

创建或关联成功后，把工具返回的真实任务 ID 写入本地 `settings.json`：`automation_ids.screen` 为预筛任务，`automation_ids.gmail` 为邮件任务。未知或未配置的角色留空。检查器和看板只读取明确绑定的任务，不扫描其他私人任务或假定某个固定 ID 属于求职。

## 配置流程

1. 使用应用提供的自动化查看/更新能力；需要读取本地配置时只读匹配任务。不要直接覆写调度器配置文件。
2. 修改提示词前保留原配置；只改用户要求的字段，保留任务 ID、时间、状态、项目、模型和通知偏好。
3. 提示词引用 `$jobhunt-assistant`，同时给出本仓库 `JobHuntBot/skills/jobhunt-assistant/SKILL.md` 的实际绝对路径作为发现失败时的入口。指明 screen 或 gmail 模式、用户确认的筛选范围，以及需要读取的参考。
4. 预筛只写预备池、摘要和 blocker，绝不晋升或申请。Gmail 只读既有申请结果，不打开邮件链接或新造投递记录。
5. 更新后读回配置，核对未要求修改的字段。不能为了测试配置而立即发起真实找岗或读取邮箱。
6. 没有可用的自动化工具时交付具体提示词和所需设置，明确尚未启用；不能声称技能本身会定时运行。

最终结果通过本地看板交付，后台运行不自动弹浏览器。任务依赖所配置执行环境、网络和连接可用；页面刷新不等于定时任务运行。
